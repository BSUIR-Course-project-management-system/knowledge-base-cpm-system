# Docs Finder Service

Микросервис для поиска научных публикаций по свободно введённой теме.

## Что используется и зачем

- **FastAPI** — HTTP API, чтобы другие микросервисы могли отправлять запросы.
- **OpenAlex** — единственный источник научных публикаций.
- **BAAI/bge-m3** — многоязычная embedding-модель для сравнения смысла русских и английских текстов.
- **Sentence Transformers** — загружает модель и преобразует тексты в векторы.
- **Cosine similarity** — измеряет близость векторов запроса и публикаций.
- **Docker** — упаковывает приложение и модель в воспроизводимое окружение.

Модель не хранится в Git. При Docker-сборке она скачивается в слой образа в `/models`.
При локальном запуске она автоматически скачивается из Hugging Face при старте приложения.

## Как работает поиск

1. API принимает `query` и желаемое количество результатов.
2. Сервис отправляет запрос в OpenAlex.
3. Для русского текста делается дополнительная попытка перевода на английский. Если переводчик недоступен, поиск продолжается с оригинальным текстом.
4. Результаты из вариантов запроса объединяются, дубликаты удаляются по DOI или названию.
5. Из OpenAlex восстанавливается аннотация: API отдаёт её в виде индекса слов по позициям.
6. BGE-M3 преобразует запросы и тексты статей в embeddings.
7. Косинусная близость рассчитывается скалярным произведением нормализованных векторов.
8. Статьи сортируются по `relevance`.

`relevance` — оценка семантической близости, а не вероятность того, что статья идеальна или научно качественна. Порог отсечения намеренно не установлен: сервис возвращает лучшие доступные результаты, не скрывая их из-за произвольно выбранного порога.

## Вариант A. Запуск через Docker (рекомендуется)

Требования: установленный Docker Desktop или Docker Engine с поддержкой Docker Compose.

Из папки `docs-finder-service`:

```bash
docker compose build
docker compose up
```

Первая сборка занимает больше времени: Docker устанавливает PyTorch/Sentence Transformers и скачивает BGE-M3. Модель крупная, поэтому нужно стабильное интернет-соединение и несколько гигабайт свободного места.

После сборки модель остаётся внутри Docker image; volume `/models` сохраняет кэш Hugging Face между запусками.

Проверка:

```bash
curl http://localhost:8003/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

## Вариант B. Локальный запуск без Docker

Требования: Python 3.11 и несколько гигабайт свободного места.

macOS/Linux:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Windows PowerShell:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Затем:

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8003 --reload
```

При первом запуске приложение скачает модель в кэш Hugging Face. Следующие запуски используют локальный кэш.

## Проверка поиска

```bash
curl -X POST http://localhost:8003/search \
  -H "Content-Type: application/json" \
  -d '{"query":"компьютерное зрение в робототехнике","limit":5}'
```

Можно также открыть Swagger UI:

http://localhost:8003/docs

Там выберите `POST /search`, нажмите **Try it out** и отправьте:

```json
{
  "query": "влияние сна на память",
  "limit": 5
}
```

## Тесты

Установите тестовые зависимости:

```bash
pip install pytest
```

Запустите из корня сервиса:

```bash
pytest -q
```

Тесты не скачивают модель и не обращаются к OpenAlex: внешние вызовы и embeddings заменяются тестовыми данными.

## Примеры ручной проверки

Проверьте разные области, чтобы убедиться, что сервис не заточен под IT:

- `компьютерное зрение в робототехнике`
- `влияние сна на память`
- `возобновляемая энергетика`
- `клиническая диагностика сердечно-сосудистых заболеваний`

Оценивайте не только наличие результатов, но и то, насколько первые 3–5 статей действительно соответствуют запросу.

## Настройки

Настройки задаются переменными окружения или файлом `.env` (образец — `.env.example`):

- `MODEL_NAME` — имя модели Hugging Face.
- `OPENALEX_MAILTO` — необязательный email для идентификации запросов к OpenAlex.
- `CANDIDATE_LIMIT` — сколько кандидатов запрашивать до семантической сортировки.
- `OPENALEX_TIMEOUT` — таймаут запроса к OpenAlex.
- `OPENALEX_RETRIES` — число повторов при временных ошибках.

## Ограничения текущей версии

- Семантическая сортировка не может найти статью, которую OpenAlex не вернул на этапе первичного поиска.
- Перевод через deep-translator — вспомогательный внешний сервис; при сбое используется оригинальный запрос.
- Если у публикации нет аннотации, сравнение выполняется только по названию.
- Для больших нагрузок стоит добавить кэширование запросов и отдельный worker для долгих операций.
